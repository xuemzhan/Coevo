# Loop 目标基线

> 本文件在 `loop-engineer` 启动 DISCOVER 阶段时被加载。它**不**记录任务进度，只描述 MVP 的最终状态与不可妥协的边界。

## MVP 终态

- 第一优先级用户故事全部完成。
- 至少完成三个专业子智能体（任务流程理解、任务分解、风险预警）。
- 两条固定编排链跑通：任务下发链、成果回传链。
- `.agent` 任务包正常流转；篡改、错误接收人、重复与重放均能被检测。
- 项目版本变更走成果包合并，冲突走字段级审核。
- 离线完全自洽：研发机断网情况下，所有门禁、本地服务、工具调用都能跑通。
- Windows 目标环境兼容（含 Win7 64-bit 任务运行环境兼容，但**不**要求 Win7 上能运行 OpenCode 自身）。

## 不可妥协边界

- 不为兼容性降低密码算法要求。
- 不在没有签名/加密的前提下写入或导出任何任务包内容。
- 不让模型结果直接改变正式任务状态。
- 不在没有审计记录的情况下改变本地配置。
- 不删除安全相关测试来"修复"失败。

## 完成定义（mvp-complete 触发条件）

全部满足：

1. 第一优先级用户故事全部 `done`。
2. 至少三个业务子智能体已发布。
3. 两条固定编排链通过 E2E。
4. `.agent` 流转、篡改、错接收人测试通过。
5. 重复与重放检测通过。
6. 项目版本冲突审核通过。
7. 本地完全离线运行通过。
8. 目标 Windows 兼容测试通过。
9. 所有 Critical/High 安全问题关闭。
10. 需求—代码—测试追踪完整。
11. 独立 `mvp-verifier` 与 `security-reviewer` 双签。
