# 示例：内部工时统计小工具开发（跨单位多角色端到端演示）

本示例用 Coevo MVP **已实现**的生产门面（`src/coevo`）完整演示一个跨单位小
工具开发项目的全过程管理：从任务输入、流程理解、结构化分解、团队推荐，
到加密任务包下发、离线工作区执行、成果回传、版本合并、风险预警、督办
会议、决策简报与知识沉淀，最后以安全审计收口。全程离线、可复现。

## 1. 场景

任务牵头单位发起“内部工时统计小工具开发”（PRJ001）：基于 Python 开发一个
支持工时录入、按人员/项目汇总统计与报表导出的小工具，工期 2026-08-01 至
2026-08-20，由两个单位跨单位协作：

| 单位 | 职责 | 流程输入格式 |
|---|---|---|
| unit_a 信息中心研发组 | 需求澄清、开发实现、文档编制 | canonical（JSON 树形） |
| unit_b 质量与测试组 | 测试用例设计、测试执行、验收评审 | tabular（表格行） |

### 角色分工（`scenario/roles.json`）

| 角色 ID | 项目角色 | 证书 | 在示例中的动作 |
|---|---|---|---|
| u.pm | 任务/项目实际负责人 | CERT-OWNER | 确认流程模型、确认基线、审批编排、合并成果、确认风险、生成简报、审批知识入库 |
| u.dev | 研发工程师 | CERT-DEV | 接收任务包、工作区执行、进展采集、回传完成汇报 |
| u.qa | 测试工程师 | CERT-QA | 接收任务包与变更包、回传延期汇报（旧基线）与最终完成汇报 |
| u.doc | 文档工程师 | CERT-DOC | 接收任务包、工作区执行（本示例不参与合并链） |
| u.review | 评审专家 | CERT-REV | 接收验收评审任务包（本示例不参与合并链） |
| u.auditor | 系统安全管理员 | CERT-AUD | 订阅并核验全程审计流 |

## 2. 目录结构

> 维护说明（2026-08-07 OPTIMIZE-12 审查结论）：`scripts/run_example.py` 的
> `main()` 是一个约 2900 行的**线性叙事演示**（CC≈77）——按 US-0..US-15 顺序
> 走完整条业务链，内部用闭包共享 `ctx`/`store`/`now` 等大量局部状态。经评估，
> 机械拆分会引入行为漂移风险且收益有限（演示脚本以可读叙事优先），故保持现状
> 并在本文档留痕；若未来要拆，建议按"阶段 + 共享上下文对象"方式重构，并以
> `python examples/run_all.py` 作为行为回归门禁。

```text
examples/tool-dev-project/
├─ README.md                      本说明
├─ scenario/                      场景输入（业务侧数据）
│  ├─ project-input.json          项目/任务输入（负责人录入）
│  ├─ roles.json                  角色、组织、证书与授权
│  ├─ flows/
│  │  ├─ unit-a-flow.json         unit_a 流程（canonical）
│  │  └─ unit-b-flow.json         unit_b 流程（tabular）
│  ├─ talent-pool.json            脱敏人才库
│  └─ members/                    各角色工作区的证据文件（模拟本地成果）
└─ scripts/
   └─ run_example.py              端到端运行脚本（US-0 ~ US-15）
```

运行产物写入 `output/run-<时间戳>-demo/`（已被 `.gitignore` 排除），包括：

- `flows/` 已确认的流程模型与映射、合并流程；
- `baseline/` 项目初始基线（R0001）；
- `orchestration/` 编排链报告与审计链数据库；
- `outbox/` 任务下发包、任务变更包、会议决策包、督办包、审计检查点包与
  成果汇报包（真实 SM2/SM4 加密 `.agent`，覆盖 6 种包类型）；
- `workspaces/` 各成员验签导入后的项目/角色工作区（任务说明、流程要求、
  交付物要求、模板、证据）；
- `identity/` 6 个角色的身份注册结果（组织/用户/终端/证书/项目角色）、
  证书指纹复用拦截与请求重放幂等演示；
- `cockpit/` 驾驶舱状态快照、前端资源（离线校验）、9 项 API 巡检响应、
  WPS 适配层 dry-run 决策、重启持久化验证与终态视图快照；
- `reports/` 成果汇报包与进展采集记录；
- `merge/` 合并记录、三方冲突与签名回执数据库（5 份回执，版本连续至 R0006）；
- `risk/` 风险预警报告；
- `supervision/` 督办事项与会议提案；
- `brief/` 阶段、风险专题、周期三类简报（各含 JSON 与可直接打开的 DOCX）；
- `knowledge/` 知识包与审计链数据库、PRJ002 复用模板生成的基线草案，以及
  完整跑通的下发链（含 PRJ002 专属任务包）；
- `audit/` 拦截决策、审计查询结果与审计事件 JSONL；
- `summary.json` 关键 ID 汇总；`NARRATIVE.md` 全程文字记录；
  `demo-report.html` 浏览器直接打开的离线自包含演示报告（含全部步骤与产物清单）。
  报告另含：两条编排链流程图、演示时间轴、合并/风险/简报结构化结果表、
  角色行动轨迹（按审计事件聚合）与“步骤 → MVP 能力”对照表。

## 3. 运行

在仓库根目录执行（全程离线，不产生任何外部网络请求）：

```powershell
python examples\tool-dev-project\scripts\run_example.py
```

现场演示也可用一键包装脚本（自动识别仓库虚拟环境，参数与运行脚本一致）：

```powershell
examples\tool-dev-project\scripts\run-demo.ps1 -Open          # 跑完自动打开报告
examples\tool-dev-project\scripts\run-demo.ps1 -Interactive   # 逐段讲解
examples\tool-dev-project\scripts\run-demo.ps1 -Serve         # 跑完保持驾驶舱
```

运行后可用独立核验脚本（只读）检查产物完整性与关键不变量：

```powershell
python examples\tool-dev-project\scripts\verify_output.py                 # 核验最新完整运行
python examples\tool-dev-project\scripts\verify_output.py --run-dir <目录>  # 核验指定运行
```

脚本会自行断言关键不变量（包可解密回读、重放门禁通过、合并版本递增、
审计摘要链校验等），任一环节失败即抛错并以非零退出码结束。运行需要仓库
锁定的 GmSSL 3.2.0 工具链（首次会自动生成测试 PKI 档案，之后直接复用
`loop/runtime/sm2-test-pki/demo`）。

运行模式：

| 模式 | 命令 | 用途 |
|---|---|---|
| 自动演示（默认） | `python examples\tool-dev-project\scripts\run_example.py` | 一口气跑完全部步骤并生成产物 |
| 交互讲解 | 上面命令加 `--interactive` | 每步暂停，按回车继续，适合现场逐段讲解 |
| 现场驾驶舱 | 上面命令加 `--serve` | 跑完后保持环回驾驶舱服务运行（默认端口 12751，可用 `--port` 调整），Ctrl+C 退出 |
| 自动打开报告 | 上面命令加 `--open` | 运行结束后用默认浏览器打开 `demo-report.html` |

运行结束后，直接双击运行目录里的 `demo-report.html` 即可看到整场演示的
图文版报告（卡片式摘要、17 步过程、产物清单，全部内联、离线可用）。

## 4. 流程与 MVP 故事对应（17 步）

| 步骤 | 演示内容 | 对应故事/验收点 |
|---|---|---|
| 1 | 角色档案、SM2 测试 PKI、授权策略；6 个角色通过 IdentityService 注册身份档案（防证书指纹复用、请求重放幂等） | US-0 身份与信任 |
| 2 | 两个单位流程解析（canonical + tabular）、映射到标准阶段、人工确认、溯源与置信度 | US-1 流程理解 |
| 3 | 跨单位合并流程 → 结构化任务/工作包/里程碑/依赖 → 初始基线 R0001 | US-2 任务分解 |
| 4 | 脱敏人才库按任务类型推荐、负荷/时间冲突预警 | US-3 团队组建 |
| 5 | 固定编排链：流程理解→分解→推荐→负责人确认→生成包（两阶段）；智能体不可用时升级人工（失败处理） | US-4 运行中枢 |
| 6 | 4 个接收人各自生成专属加密任务包并回读校验 | US-5 任务下发 |
| 7 | 隔离区→验签→重放门禁→原子导入→项目/角色工作区释放；同一任务包再次导入被重放拦截 | US-6 工作区初始化 |
| 8 | 环回驾驶舱：页面 + 9 项 API 巡检（含响应内容校验）、前端离线性校验、WPS 适配层 dry-run 决策、重启后状态持久化恢复 | US-7 本地驾驶舱 |
| 9 | 工作区文件感知（watcher）→ 进展识别、人工修订/驳回/确认；拒绝仅凭文件时间（AC-7） | US-8 进展采集 |
| 10 | 生成真实加密 RESULT_SUBMISSION 成果包（开发完成 + 测试延期） | US-9 成果回传 |
| 11 | 正常合并 → R0002；旧基线汇报触发三方冲突挂起（AC-3/AC-5/AC-6）；TASK_CHANGE 下发；按新基线合并 → R0003，签名回执 | US-10 状态合并 |
| 12 | 合并后自动风险分析：延期（严重度 4）、前置未完成、会议建议 | US-11 风险预警 |
| 13 | 风险转督办、督办包下发（SUPERVISION_NOTICE）、会议提案（议题/背景/待决策）、结论转整改任务并下发会议决策包 | US-12 督办与会议 |
| 14 | 负责人确认风险后生成阶段简报（仅使用已确认状态 + 已批准 WPS 模板）并渲染简报 DOCX | US-13 决策简报 |
| 14b | 第二轮任务循环：会议结论转整改任务 → 任务包下发 → 成员回传 → 合并（回执链连续至 R0004） | 演示闭环第 17 步 |
| 14c | 基于第二轮合并结果生成“风险专题”简报（简报类型扩展） | US-13 简报类型 |
| 14d | 基线同步（TASK_CHANGE）后全员成果回传与结项：文档、验收评审汇报合并（连续至 R0006），生成“周期”简报 | 全员回传闭环 |
| 15 | 知识包汇总、复盘草稿、可复用模板、审批入库并持久化；PRJ002 复用模板并完整跑通任务下发链（知识复用闭环） | US-14 成果沉淀 |
| 16 | 异常包拦截（篡改/过期/重放/接收人不匹配）、真实字节篡改拒绝、错误接收人解密拒绝、审计流查询、审计检查点包导出、摘要链校验 | US-15 安全审计 |
| 17 | 汇总产物与关键 ID（含结项状态），生成离线 HTML 演示报告（流程图/时间轴/结果表/角色轨迹/步骤对照）；`--serve` 展示双项目终态驾驶舱（PRJ001 结项 + PRJ002 复用），`--open` 自动打开报告 | — |

## 5. 安全与边界说明

- 本示例使用演示级测试 PKI（`DEMO_PROFILE`）与内存演示签名器，仅用于展示
  流程；正式系统使用受保护密钥句柄（CNG/智能卡）与国密认证模块。
- 私钥、口令等敏感字节不进入本脚本与产物：GmSSL 助手只返回密码运算结果。
- 所有正式状态变更（编排确认、合并、风险发布、简报发布、知识入库）都有
  人工确认节点；模型/规则产物不会自动写入正式状态。
- 任务包内的脚本、可执行文件与未授权文件类型不会被执行；示例仅释放
  文本与无宏 DOCX 模板。
- 演示时间线固定在 2026-08；版本一律使用整数版本号与 `PRJ001-Rxxxx` 主
  版本标识，不以时间戳作为版本依据。
