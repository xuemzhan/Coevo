# 分布式任务管理具身智能体系统

# MVP参考选型

## 一、文档定位

本部分给出MVP阶段推荐技术组合，用于缩短开发周期、降低部署依赖并验证核心模式。

本部分属于参考选型，不替代《强制性技术约束》。在满足强制性要求的前提下，开发团队可替换具体语言、框架和组件，但应经过技术评审并说明替代方案。

---

## 二、MVP验证目标

MVP优先验证：

1. 不同单位任务流程解析；
2. 结构化任务分解；
3. 脱敏人才推荐；
4. 运行中枢固定编排链；
5. `.agent`任务包加密流转；
6. 本地离线工作区；
7. 进展和成果采集；
8. 项目版本冲突审核；
9. 基础风险预警；
10. “开悟”WPS工具调用；
11. 基础决策简报；
12. 审计篡改发现。

MVP不以一次性满足全部正式安全能力、全部操作系统和全部智能体场景为目标。

---

## 三、MVP总体架构

建议采用“中心端＋离线客户端”双组件架构。

### 3.1 中心端

中心端包含：

* 运行中枢；
* 项目主状态；
* 任务流程模型；
* 智能体能力目录；
* 固定编排流程；
* 风险和简报能力；
* 任务包生成与合并；
* 审计管理。

### 3.2 本地客户端

客户端包含：

* 本地驾驶舱；
* 本地智能体运行时；
* 任务包导入导出；
* 工作区管理；
* 文档和成果感知；
* “开悟”工具适配；
* 本地数据库；
* 本地审计日志。

### 3.3 MVP编排链

首期建议只实现两条固定编排链。

#### 编排链A：任务策划

> 任务输入
> → 任务流程理解
> → 任务分解
> → 人才推荐
> → 负责人确认
> → 任务包生成。

#### 编排链B：状态回传

> 成果包导入
> → 版本差异审核
> → 项目主版本更新
> → 风险预警
> → 决策简报生成
> → 负责人确认。

## 四、参考技术组合

| 模块      | MVP参考选型              | 说明             |
| ------- | -------------------- | -------------- |
| 中心端服务   | Go或Java轻量服务          | 根据团队现有能力选择     |
| 本地客户端   | Go                   | 便于生成低依赖可执行程序   |
| 本地Web服务 | Go标准HTTP服务或轻量框架      | 仅绑定环回地址        |
| 前端      | Vue静态构建              | 不在终端运行构建工具     |
| 样式      | Tailwind构建产物或轻量CSS   | 所有资源本地化        |
| 静态资源    | 嵌入可执行文件或只读资源目录       | 禁止CDN          |
| 中心数据库   | PostgreSQL或现有受控数据库   | 保存任务主状态和编排记录   |
| 本地数据库   | SQLite               | 保存项目索引、状态和日志索引 |
| 文件存储    | 受控文件系统               | 大文件不直接存入数据库    |
| 目录监听    | fsnotify或系统原生文件事件    | 支持文件写入完成判断     |
| 编排机制    | Go状态机或轻量工作流模块        | MVP不引入大型工作流平台  |
| 智能体接口   | JSON Schema＋统一调用协议   | 支持版本和错误码       |
| 模型适配    | 统一模型网关/本地适配器         | 避免绑定单一模型       |
| 任务包     | 自定义`.agent`安全封装      | 遵循独立协议规范       |
| 审计      | JSON Lines＋摘要链＋签名检查点 | 实现篡改可检测        |
| 安装包     | 离线安装包＋制品签名           | 支持升级和回滚        |

## 五、操作系统参考策略

### 5.1 正式MVP主版本

主版本宜选择仍处于支持期内的Windows环境，用于验证完整能力，包括：

* 本地驾驶舱；
* 智能体运行时；
* 模型调用；
* WPS工具调用；
* 任务包管理；
* 本地审计。

### 5.2 Windows 7兼容版本

Windows 7建议采用独立兼容分支，功能控制为：

* 任务包导入导出；
* 本地工作区；
* 本地驾驶舱；
* WPS文档打开；
* 进展手工确认；
* 基础成果包生成；
* 本地审计。

Windows 7兼容版可暂不支持：

* 当前浏览器内核；
* 复杂本地模型；
* 动态插件；
* 高级可视化；
* 实时在线调度；
* 全量自动升级。

### 5.3 界面实现

正式MVP主版本可采用：

* 本地浏览器访问环回服务；或
* 受控桌面壳。

Windows 7兼容版本宜优先采用系统浏览器访问本地服务或经验证的轻量桌面界面，不强制使用WebView2。

---

## 六、本地客户端参考实现

### 6.1 进程结构

建议包含：

1. 主客户端进程；
2. 本地HTTP服务；
3. 目录监听模块；
4. 任务包处理模块；
5. 工作区模块；
6. 工具适配模块；
7. 审计模块。

MVP可在同一进程中运行多个模块，不要求每个子智能体独立进程。

### 6.2 工作目录

Windows环境建议使用：

```text
%LOCALAPPDATA%\KaiwuAgent\
├─ inbox\
├─ quarantine\
├─ outbox\
├─ archive\
├─ workspaces\
├─ temp\
├─ logs\
├─ config\
└─ secure\
```

`secure`目录只保存密钥引用、加密配置或密码模块接口信息，不保存明文私钥。

### 6.3 本地服务

建议：

* 动态选择可用端口；
* 仅绑定`127.0.0.1`；
* 启动时生成短期本地会话令牌；
* 页面通过令牌访问本地接口；
* 限制Host和Origin；
* 写操作启用防跨站请求令牌。

### 6.4 单实例

客户端应采用单实例机制，防止多个进程同时处理同一任务包或写入同一数据库。

## 七、前端参考实现

### 7.1 功能范围

MVP前端只需实现：

* 项目和角色切换；
* 任务列表；
* 里程碑；
* 交付物；
* 风险提示；
* 任务包导入导出；
* 差异审核；
* 智能体编排状态；
* 审计记录查询；
* WPS文档打开。

### 7.2 资源打包

建议在构建阶段完成：

* Vue编译；
* Tailwind样式生成；
* 图标本地化；
* 字体本地化；
* 资源压缩。

终端运行时不得依赖Node.js、npm或网络下载。

### 7.3 可视化

MVP甘特图和任务关系图宜采用轻量组件。

如组件兼容性或离线安全难以保证，可先采用表格、时间轴和层级树，不应因复杂可视化延误核心闭环。

## 八、智能体和模型参考实现

### 8.1 子智能体实现方式

七类专业子智能体可采用同一模型服务＋不同能力配置的方式实现，不要求每个智能体部署独立模型。

每个智能体通过以下内容区分：

* 系统指令；
* 输入数据结构；
* 可访问工具；
* 输出数据结构；
* 业务规则；
* 人工确认点。

### 8.2 模型适配器

建议定义统一接口：

```text
ModelAdapter.Invoke(
  model_id,
  agent_id,
  input_schema,
  input_data,
  tool_policy,
  timeout
)
```

返回：

```text
result
evidence
reasoning_summary
model_version
requires_confirmation
error_code
```

不得保存或输出模型私有思维过程。系统只保留可供业务审查的依据摘要。

### 8.3 MVP模型能力

MVP优先使用：

* 任务流程要素提取；
* 任务分解建议；
* 进展摘要；
* 风险规则辅助分析；
* 决策简报生成；
* 复盘草稿。

涉及责任认定、正式风险和正式进度的结论由人工确认。

## 九、运行中枢参考实现

### 9.1 状态机

MVP建议采用代码化轻量状态机，而不是直接引入大型BPM平台。

编排实例至少保存：

* `workflow_instance_id`；
* `workflow_type`；
* `project_id`；
* 当前步骤；
* 已完成步骤；
* 待审批步骤；
* 失败步骤；
* 重试次数；
* 输入输出摘要；
* 审计关联编号。

### 9.2 事件表

建议建立统一事件对象：

```text
event_id
event_type
project_id
task_id
source
occurred_at
sequence_no
payload
deduplication_key
```

### 9.3 人工审批

MVP可在驾驶舱中实现审批卡片，支持：

* 查看输入；
* 查看建议；
* 同意；
* 修改后同意；
* 驳回；
* 转人工处理。

---

## 十、任务包参考实现

MVP应完整遵循《.agent任务包协议规范》。

参考实现可采用：

* 自定义固定包头；
* 规范化JSON外层头；
* 标准压缩归档作为加密载荷；
* SM3文件摘要；
* SM2数字签名；
* SM4认证加密；
* SM2会话密钥封装。

任务包内部使用标准压缩格式是允许的，但必须封装在自定义密码信封中，不得仅修改普通压缩文件后缀。

---

## 十一、密码能力参考实现

### 11.1 原型阶段

原型阶段可使用经过测试的密码库验证：

* SM2签名和验签；
* SM2密钥封装；
* SM3摘要；
* SM4加密和解密。

### 11.2 正式试点

进入正式任务环境前，应替换或接入批准的密码产品、密码模块和密钥介质。

### 11.3 随机数

会话密钥、随机数和认证加密Nonce必须来自密码学安全随机数源，不得使用普通伪随机函数或时间戳生成。

---

## 十二、WPS与“开悟”参考实现

### 12.1 基础调用

MVP优先实现：

* 从驾驶舱打开WPS文档；
* 根据模板生成副本；
* 将任务元数据写入模板；
* 调用“开悟”插件生成或修改材料；
* 保存为新版本。

### 12.2 深度集成

深度插件接口、COM接口或其他自动化接口，应根据实际WPS版本进行适配验证。

不得假定所有终端WPS版本具有完全一致的自动化能力。

### 12.3 安全限制

* 仅打开允许目录内的文件；
* 文件路径必须规范化；
* 不允许任务包控制任意启动参数；
* 禁止自动运行宏；
* 修改前保留原始版本。

---

## 十三、审计参考实现

### 13.1 日志格式

建议采用JSON Lines，每条日志包括：

```text
log_id
timestamp
actor_id
client_id
agent_id
project_id
task_id
action
result
error_code
object_digest
previous_log_digest
current_log_digest
```

### 13.2 签名检查点

建议每达到以下条件生成签名检查点：

* 固定日志条数；
* 固定时间周期；
* 应用正常退出；
* 项目主版本更新；
* 任务包导入或导出完成。

### 13.3 导出

支持将审计日志和签名检查点导出为独立审计包，由安全管理员留存。

## 十四、MVP性能参考指标

以下指标应在明确测试环境后最终确认：

| 场景         | 参考目标   |
| ---------- | ------ |
| 普通页面打开     | 3秒以内   |
| 本地任务查询     | 2秒以内   |
| 小型任务包基础校验  | 10秒以内  |
| 目录文件发现     | 5秒以内   |
| 任务包生成成功率   | 不低于95% |
| 重复包识别      | 100%   |
| 异常包拦截      | 100%   |
| 项目状态合并可追溯  | 100%   |
| 智能体固定编排成功率 | 不低于95% |

模型推理、报告生成和大型附件加解密应单独统计，不纳入普通页面响应时间。

8. 本地工作区和驾驶舱；
9. 成果回传和差异合并；
10. 风险分析和决策简报；
11. WPS基础适配；
12. 审计和异常处理；
13. 离线安装包；

## 十六、MVP不建议事项

MVP阶段不建议：

1. 引入大型微服务体系；
2. 引入复杂分布式数据库；
3. 为每个智能体部署独立模型；
4. 一次性建设通用低代码编排平台；
5. 实现全自动项目计划优化；
6. 同时兼容所有WPS和Windows版本；
7. 将正式密码合规全部压在原型阶段完成；
8. 建设复杂三维或大屏可视化；
9. 允许智能体动态下载未知工具；
10. 允许用户自行安装未审核插件。
